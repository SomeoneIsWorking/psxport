# Codemap

This map owns subsystem placement and dependency direction only. Product intent is
`docs/project-goals.md`; factual capability state is `docs/project-state.md`; migration ordering and
acceptance gates are `docs/migration.md`; atomic work is `docs/issues/`.

## Architecture layers

The intended dependency direction is:

`consumer title policy -> psxport composition/API -> PSX CPU and platform owners -> host libraries`

The CPU executor calls platform/HLE/native services only through narrow callbacks after synchronizing
guest-visible state. Platform, renderer, audio, UI, and diagnostic owners never choose a guest CPU
engine. Test-oracle targets may depend on the production CPU state and memory seams; the gameplay
library never depends on a test oracle.

## Who owns it

One chain per turn, hop by hop. A hop that is not in its owner's file is the defect to look for first.

### Native override -> guest call

| Hop | Owner | What it decides |
| --- | --- | --- |
| Registration | `psx::cpu::installNativeOverride` (`runtime/cpu/native_dispatch.cpp`) | Builds the `(active image identity, address)` key and refuses a null handler, an address no image owns, and a key that already has an owner. A title that must not continue without its override gets the aborting form; the returning form is for a refusal that is a reportable outcome |
| Dispatch | `NativeDispatcher::classify` -> `invoke` / `dispatchGuest` | Whether the address is a native override, a host service, or plain guest code, from a cache discarded whenever an input changes |
| A guest call that outlives its turn | `ResumableGuestCall::begin` -> `advance` (`runtime/cpu/resumable_guest_call.cpp`) | The boundary captured BEFORE the first dispatch and latched into `r[31]`; one display field per segment; a segment with no guest cycles is refused rather than repeated; the turn cap is a stated count of display fields; each stop is Returned, Suspended or Refused |
| A call that must finish now | `callGuestToReturnResuming` / `callOriginalResumingToReturn` | The same loop run to its return address, aborting on a refusal with the owner, entry, return address, turn and reason named. The `Original` form resolves the key and re-establishes the suppression scope on every resume, so guest code inside an original cannot re-enter its own override |
| The run's measure of those calls | `GuestCallCensus::recordCompleted` -> `log` (`runtime/cpu/guest_call_census.cpp`) | Completed, resumed, deepest turns, cycles — recorded per `Core` by the call that made them, reported once at run end with its denominators |

### Product boot -> the field turn

| Hop | Owner | What it decides |
| --- | --- | --- |
| Per-Core devices | `psx::Machine::bindDevices` (`runtime/psx/boot/machine.cpp`) | `init` then `bind` per device in the measured order (GTE first), then `r[4] = 1`, `r[5] = 0`. The title's `Game` and installed runtime already exist — a `Game` reads the installed runtime as it is constructed |
| Title overrides, then preflight | `psx::Machine::prepare` -> `GameRuntime::registerOverrides` -> `FrameLoopShell::prepareProduct` | Which leaves are native, and refuses a product with no finite frame owner before any guest code can run |
| Control channel and cap | `psx::Machine::attachControlChannel` -> `DbgServer::attach` + `store_observe_attach` | Whether a client is going to drive the run, and the frame cap this run must use — 0 when one is, because a cap exists to bound an unattended smoke run |
| One field | `psx::FieldTurn::beginField` -> `FrameLoopShell::step` (`FrameDriver::stepFrame`) -> `psx::FieldTurn::endField` | Pause and watchdog re-arm before the body, RAM-dump frame and one command after it, so a read never sees a half-completed command and no field runs under a timeout nobody re-armed. The frame BODY is the title's. Called by `native_boot`, by `psx::Machine::stepFrame`, and by a title's own loop |
| The loop | `psx::Machine::run` | Ends on the cap, a window close (`HostInput::quitRequested`) or a client `quit` (`DbgServer::quitRequested`), then prints the guest ledger and the guest-call census |
| The framework spine | `native_boot_run` -> `psx::Machine` steps (`runtime/psx/boot/native_boot.cpp`) | The whole spine — preflight, host diagnostics, render path, boot movies, display clear, crt0, boot prologue, loop — for a product with nothing of its own to add. It composes the same owner a title-owned loop does; what stays here is the REPL budget/prompt and the frame-cap policy (headless default, pad-replay lift, REPL drive), which are THIS loop's mode rather than a product's step |

### Host input -> pad -> guest

| Hop | Owner | What it decides |
| --- | --- | --- |
| SDL event queue | `psx::input::HostInput::drainEvents` (`runtime/psx/input/host_input.cpp`) | The ONE drain. Records delivered key state, hands the event to the overlay, ends the process on a window close |
| Key state, controllers, keyboard gate | `HostInput::poll(bool windowAvailable)` | The active-low PSX mask for this turn. `windowAvailable` is the caller's answer; with no window there is no host input, so it answers `kNoButtons` and drops a pending debug edge |
| Debug edges | `HostInput::takePauseRequest` / `takeFrameStepRequest` -> `DbgServer::togglePause` / `addStep(1)` | The keys are detected here, the ACTION stays in the debug channel, so all six products that never call `honourPause` still pause |
| Effective mask | `Pad::pollHostInput` (`runtime/psx/input/pad_input.cpp`) | The one pump: drains, then assigns the host mask ONLY when a window is up, so a forced, replayed, restored or host-driven mask survives a headless leg |
| Pad frame | `Pad::serviceFrame` | force/hold -> REPL drive -> host suppression -> session record/replay, each able to win over the one before; edges are latched only after the final mask |
| Guest | `Pad::fillBuffer` -> the registered slot buffers | The 4-byte digital packet per VBlank; slot 1 writes `0xFF` when that title declares no second controller |

Every pump site goes through `HostInput`, never through a second drain:

| Site | Calls | Why |
| --- | --- | --- |
| Frame service | `Pad::pollHostInput` | the ordinary per-frame pump |
| Blocking movie (`Fmv::playToEnd`) | `Pad::pollHostInput` | a movie turn is a served host frame, so the skip reads the pad owner's serviced mask and is replayable |
| Debug pause wait (`DbgServer::honourPause`) | `Pad::pollHostInput` | a paused run must still see the key that resumes it; it must not tick the pad-frame clock |
| SCEA splash (`runtime/psx/boot/native_stub.cpp`) | `Pad::pollHostInput` | Start during the splash is the same press as any other frame |
| Present path (`gpu_vk.cpp` 4 sites, `gpu_vk_api.cpp` 1) | `HostInput::drainEvents` | records state and keeps the overlay fed without consuming the pad's edge; the next `poll` resolves it |

## Where does new work go?

- Lightrec initialization or run-loop behavior -> runtime/cpu/lightrec_executor.*
- CPU register/cycle transfer -> runtime/cpu/lightrec_executor.* and the canonical state in runtime/psx/core/
- A new host-visible execution stop -> runtime/cpu/execution_exit.*
- Resident/overlay identity or generation -> runtime/cpu/image_identity.*
- Native override or original-call semantics -> runtime/cpu/native_dispatch.*
- A boot step every product shares -> runtime/psx/boot/machine.*; a step of the framework spine as a whole -> native_boot_run (declared in runtime/psx/boot/native_boot.h); a per-field service (pause, watchdog re-arm, mid-run RAM dump, one serviced command) -> runtime/psx/frame/field_turn.*, from whichever loop is being written
- A native-to-guest call that crosses display fields, its boundary latch, cap and refusals -> runtime/cpu/resumable_guest_call.*
- The run's count of calls that needed a resume -> `Core::guestCallCensus()` (runtime/cpu/guest_call_census.*), reported once at run end
- Proving a native override equals its original -> runtime/cpu/override_differential* (armed by PSXPORT_OVERRIDE_DIFF), gated by tools/port/override_differential_gate.py
- Which guest functions a run reached -> runtime/cpu/function_reach* (armed by PSXPORT_REACH_REPORT)
- CPU/DMA/loader/debugger/savestate code invalidation -> runtime/cpu/invalidation.*
- Lightrec block-cache or executable-memory internals -> the pinned Lightrec fork, not psxport
- Interpreter semantics or independent state comparison -> tools/oracle/, never the gameplay library
- Making a port's `external/psxport` exist -> `tools/psxport_fetch.py` (ships), never a third copy
- Decompiling guest code, or a title's load base / text window -> tools/decomp/ and its manifest.json
- A question about what a run of guest words IS (entry, return, direct/indirect call) -> tools/decomp/structure.py, and nowhere else
- A decompilation that is turning into a build input, corpus, or install-time translation -> nowhere; that is a stop, not a new owner
- A per-title branch inside the decomp reader -> tools/decomp/manifest.json; the reader grows a `kind`, not an `if` per title
- Comparison-run role and enhancement suppression -> runtime/psx/debug/diagnostic_run.h and the configuration owner
- Fallback admission and telemetry -> runtime/cpu/fallback_policy.h and runtime/cpu/lightrec_executor.*
- PSX device behavior -> its existing `runtime/psx/<device>/` owner (`cd/`, `audio/`, `gpu/`, `platform/`, `input/`)
- Title-specific address, native body, or frame/task policy -> the consuming game repository
- Environment/settings parsing -> the configuration owner
- Logging behavior -> Lucentt; one call site stays in the module that owns the event

## Source tree

`runtime/psx/` was one flat directory of 320 files until step 2 of the structure work (2026-10-03).
Nothing in it changed ownership that day: the same classes, the same namespaces, the same includes —
only the placement. Every subsystem directory is exported on psxport's PUBLIC include path, so
`#include "x.h"` resolves by basename from a consumer exactly as it did before.

```text
runtime/
  cpu/       the Lightrec executor boundary: lifetime, typed exits, image identity, native
             dispatch, resumable guest calls, invalidation, override differential
  psx/
    boot/    what comes up, in order: psx::Machine (the shared composition), native_boot_run

    host/    the multi-title product host: selector, panels, title sessions, the catalog contract

    input/   host input, the pad, its record/replay and phase replay, SIO

    debug/   the live control channel, the REPL, and the census/capture instrumentation
```
